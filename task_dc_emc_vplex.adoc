= Configuring the EMC VPLEX data collector
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead] 
This data collector acquires inventory and performance data from EMC VPLEX or Metro Node storage systems. For Vplex configuration, the data collector requires an IP address of the VPLEX/Metro Node management server and an administrative level domain account. On Metro Node systems, DII requires "service" or "admin" level accounts because lesser privileged users are not able to browse the management station's file system to retrieve performance archive artifacts for performance reporting

NOTE: Vplex / Metro Node management stations may have visibility into 2 Vplex / Metro Node storage arrays if you have a geographically distributed configuration. In such configurations, the DII data collector will discover both storage arrays involved with one collector. This may not be your desired state, which you can use the collector's exclusion capability to control - VPlex/Metro environments in such topologies will generally have 2 management stations, one per site. 

NOTE: Data Infrastructure Insights' performance collection from VPLEX/Metro Node clusters requires that the performance archive service be operational, in order to populate the .CSV files and logs that Data Infrastructure Insights retrieves via SCP-based file copies. NetApp has observed that many VPLEX firmware upgrade/management station updates will leave this functionality non-operational. Customers planning such upgrades may want to proactively ask Dell/EMC if their planned upgrade will leave this functionality inoperable, and if so, how can they re-enable it to minimize gaps in performance visibility? Cloud Insight's VPLEX performance code will assess on each poll whether all the expected files exist, and if they are being properly updated; if they are missing or stale, Data Infrastructure Insights will log performance collection failures.

== Requirements

* An IP address of the VPLEX Management Console
* Administrative level domain account for the VPLEX server
* Port 443 (HTTPS).  Requires outbound connectivity to TCP port 443 on the VPLEX/Metro management station for Inventory gathering
* Port 22 (SSH).  Requires outbound connectivity to TCP port 22 on the VPLEX/metro management station to retrieve performance archive files via SCP

== Troubleshooting
Some things to try if you encounter problems with this data collector:

=== Inventory

[cols="50,50", options="header"]
|===
|Problem:|Try this:
|Error: User authentication failed.
|Make sure your credentials for this device are correct.
|===

=== Performance

[cols="50,50", options="header"]
|===
|Problem:|Try this:
|Error: VPLEX performance for version below 5.3 is not supported.
|Upgrade VPLEX to 5.3 or above
|Error: No enough data collected.
|•	Check collection timestamp in log file and modify polling interval accordingly
•	Wait for longer time
|Error: Perpetual Log files not being updated.
|Please contact EMC support to enable updating the perpetual log files
|Error: Performance polling interval is too big.
|Check collection timestamp in log file ${logfile} and modify polling interval accordingly
|Error: Performance Remote IP address of VPLEX Management Console is not configured.
|Edit the data source to set Performance Remote IP address of VPLEX Management Console.
|Error: No performance data reported from director
|•	Check that the system performance monitors are running correctly
•	Please contact EMC support to enable updating the system performance monitor log files
|===
